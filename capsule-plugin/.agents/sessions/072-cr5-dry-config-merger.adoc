== Livrables

=== CR-5.1–5.7 : Refactor production (1 fichier)

`src/main/kotlin/capsule/CapsuleConfigMerger.kt` (322 → 302 lignes, -19 net) :

. `merge()` unifié — `yaml: CapsuleConfig? = if (yamlLoaded) yamlConfig else null`,
  dispatch sur `yaml?.xxx` nullable. Branche `if (!yamlLoaded)` supprimée.
. 10 méthodes `mergeXxxConfig`/`mergeXxxConfigNoYaml` → 5 méthodes unifiées
  acceptant `yaml: T?` nullable (input, tts, capture, distrib, manim).
. 4 helpers génriques extraits :
  * `mergeStr(cli, key, yaml: String?, props, env)` — CLI > YAML > Props > ENV
    avec heuristic `isNotBlank()` pour strings.
  * `mergeInt(cli, key, yaml: Int?, props)` — CLI > YAML > Props (pas de ENV,
    pas de "blank" concept pour Int).
  * `mergeDouble(cli, key, yaml: Double?, props)` — CLI > YAML > Props.
  * `mergeBoolean(cli, key, yaml: Boolean?, props)` — CLI > YAML > Props.
. Sémantique préservée : `cliBoolean` utilise `toBoolean()` (lenient) et non
  `toBooleanStrictOrNull()` — l'ancien code des merges utilisait `?.toBoolean()`.
. Helper `String.ifNotBlankOrElse` conservé (utilisé par aucun merge après
  refactor, mais potentiellement par tests internes — conservé par prudence).
