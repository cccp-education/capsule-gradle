== Contexte

US-4 clôt CAP-CONTEXT. La composition Remotion (`Capsule.jsx`) hardcodait son
fond (`PAGE_BACKGROUND`), donc une marque ne pouvait pas habiller la capsule :
les tokens du deck (CAP-CONTEXT, injectés par `ViralDeckBuilder` as
`--capsule-background` / `--accent-color`) étaient **ignorés**.

Chaîne des tokens (rappel) : `VisualIdentity` (domaine `capsule.viral`) →
`ViralDeckBuilder` émet `:root { --capsule-background; --capsule-typography;
<brand tokens> }` dans le `<head>` du deck → `Capsule` (Remotion) rejoue ce
`headHtml` dans la composition. Le token était donc **déjà** disponible ; il ne
restait qu'à le **lire**.

== Livrable — `Capsule.jsx` lit les tokens

* `DEFAULT_BACKGROUND` (ex-`PAGE_BACKGROUND`) devient un simple **repli**.
* `BRAND_BACKGROUND = var(--capsule-background, ${DEFAULT_BACKGROUND})` — fond
  de composition (remplace le littéral hardcodé dans les deux `AbsoluteFill`).
* `BRAND_ACCENT = var(--accent-color, rgba(255,180,58,0.85))` — barre de
  progression.
* Aucun changement Kotlin : les tokens circulent déjà via le deck `headHtml`.

Effet : une marque qui pose `--capsule-background` / `--accent-color` habille la
capsule **sans** que `Capsule.jsx` la connaisse ; sans brand book, le rendu
historique est **inchangé** (repli).

* **Token d'abord, littéral en repli** (`var(--token, <fallback>)`) — la marque

  sans brand book).
* **Pas de nouvelle prop Remotion** — les tokens circulent déjà par `headHtml`

* **Pas de threading Kotlin** — `ViralDeckBuilder` émet déjà `--capsule-background`
