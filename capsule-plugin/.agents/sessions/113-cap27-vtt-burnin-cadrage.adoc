== Constat central — prémisse du backlog caduque

La compatibilité VTT **fonctionne déjà**. Le filtre FFmpeg `subtitles=`
auto-détecte le format par extension de fichier (`.vtt` → demuxer WebVTT).
`SubtitleBurnInServiceImpl.burnIn` (L66-72) passe le chemin absolu du
fichier sous-titre directement au filtre — donc un `.vtt` est accepté sans
modification du code.

Vérification empirique réelle (ffmpeg 6.1.1, `/usr/bin/ffmpeg`,
config `--enable-libass`) : `in.webm` (testsrc 3s) + `sub.vtt` (format
exact de `VttGenerator` : `WEBVTT` + timestamps `HH:MM:SS.mmm` + cue
index) → `ffmpeg -y -i in.webm -vf "subtitles=sub.vtt:force_style='...'"
-c:a copy out.webm` → **exit 0**, WebM 23105 o valide (audio préservé).

Conséquence : CAP-27 = cible de **couverture test**, pas un fix de
compat. Le seul gap : zéro scénario `@vtt`, commande ffmpeg inline non
testable.
