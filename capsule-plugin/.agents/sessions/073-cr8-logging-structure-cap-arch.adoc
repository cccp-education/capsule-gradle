== CR-8 — Refactor logging structuré

=== Problème

`CapsulePlugin.kt:40-48` — 1 `logger.lifecycle` monolithic avec 13 placeholders :

----
"Capsule config resolved: engine={}, voice={}, language={}, vw={}x{}, parallel={}, subtitle={}/{}/burnIn={} manim=[path={}, quality={}, scriptsDir={}, outputDir={}]"
----

Impossible à parser visuellement. 13 placeholders croisés, ordre fragile.

=== Solution

Extraction de `CapsuleConfigLogger` (object pur, domaine `capsule.config`) :
- `formatConfigLog(config: CapsuleConfig): List<String>` → 4 lignes structurées
- `formatTtsLine` — `Capsule TTS: engine=X, voice=Y, language=Z`
- `formatCaptureLine` — `Capsule Capture: vw=WxH, parallel=B`
- `formatSubtitleLine` — `Capsule Subtitles: subtitle=B, subtitleFormat=F, burnIn=B`
- `formatManimLine` — `Capsule Manim: path=P, quality=Q, scriptsDir=S, outputDir=O`

Tokens préservés verbatim (`engine=`, `quality=`, `subtitle=`, `subtitleFormat=`,
`burnIn=`, `scriptsDir=`) → Cucumber steps existants (`@config`) restent verts.

`CapsulePlugin` remplace le bloc monolithic par :
----
CapsuleConfigLogger.formatConfigLog(mergedConfig).forEach { line ->
    project.logger.lifecycle(line)
}
----
