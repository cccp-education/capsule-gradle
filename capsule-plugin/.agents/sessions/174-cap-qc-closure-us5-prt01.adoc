== A — CAP-QC-VOICE US-5 (optionnel) — karaoké sur timings ASR

* **Domaine pur** `capsule.viral` : `TimedWord` + `WordTimingsJson.parse` (whisper
  `segments[].words[]`, tolérant : document vide/malformé → liste vide) +
  `KaraokeWordPlanner.plan(beats, timings)` — les timings mesurés sont **clampés** à la
  fenêtre du beat et le repli **proportionnel** s'applique dès qu'un mot du beat n'est
  pas apparié (jamais de timing inventé).
* `RenderViralSubtitlesTask` : entrée optionnelle `wordTimingsFile`
  (`-Pcapsule.viral.wordTimingsFile`).
* Rétro-compatible (timings vides = ancien comportement). +5 unit (`WordTimingsTest`) +
  1 scénario BDD (`capsule_viral_karaoke.feature`).

== B — CAP-QC PRT-01 (intrusif) — dit/lu + cache par contenu

* **Domaine pur** `capsule.voice.PronunciationLexicon` : `spoken(display)` (sigles
  épelés `API` → `A P I`, symboles étendus `%` → `pour cent`), `reversals()` (dit →
  affiché), `cacheKey(spoken)` (8 hex SHA-256).
* **Cache par contenu, non intrusif** : `CapsuleBuildTask`, opt-in
  `tts.pronunciationEnabled` — la voix prononce la forme **dite**, et une prise
  existante n'est réutilisée que si le sidecar `<file>.key` correspond à la clé du
  texte dit (éditer une prononciation n'invalide que les prises concernées).
  **Décision** : le nom canonique `slide-NN.mp3` et le lookup `CapsuleVideoTask` sont
  **inchangés** (le cadrage proposait `slide-NN-<key8>.mp3` ; le sidecar atteint le
  même but sans toucher les 8 sites de résolution audio et leurs tests — moindre
  risque pour le même contrat d'économie d'encre). Défaut off = comportement strictement
  identique.
* `TtsConfig.pronunciationEnabled` 4 sources + extension/conventions/push.
* +6 unit (`PronunciationLexiconTest`) + merger + 1 scénario BDD
  (`capsule_voice_quality.feature`).
