== Contexte

Suite du diagnostic e2e CAP-SHORT (S-145, `BACKLOG.adoc` § CAP-SHORT) : le
**moteur** capsule est mature (domaine viral ~95 %, socle FFmpeg ~95 %), mais
l'e2e viral est à ~20 %. Le trou n°1 : `ViralStoryboardBuilder.build()` n'émet
qu'un **document AsciiDoc** — aucun deck capturable. Sans deck, **rien à
filmer** : c'est le vrai déblocage du rendu (US-1a, prérequis d'US-1b
« orchestration `renderViralVariants` »).

== Livrable — `ViralDeckBuilder`

Objet pur (domaine `capsule.viral`, zéro I/O / navigateur / FFmpeg) :

* `ViralDeckBuilder.WIDTH/HEIGHT` = 1080×1920 (9:16, aligné `ViralViewport`).
* `build(storyboard): String` — document HTML auto-suffisant :
  **une `<section>` par beat** (capturable par le socle FFmpeg `SCREENSHOT`).
  * `data-role` (hook/development/cta), `data-duration` (secondes, pour le
    montage), `data-manim` (scène) et `data-asset` quand portés.
  * contenu : le `role` (kick) + l'`intent` (titre), **HTML échappé**
    (`capsule.HtmlEscape`) — anti-XSS (CR-4).
  * identité visuelle : les tokens de `VisualIdentity` sont injectés en
    variables CSS (`:root { --accent-color: … }`), la typo et le fond sont
    paramétrés ; sans contexte, valeurs par défaut neutres.
  * déterministe (test byte-identique).

Câblage Gradle :

* `GenerateViralCampaignTask.deckOutput: RegularFileProperty` (`@OutputFile`) ;
  écrit `ViralDeckBuilder.build(storyboard)`.
* `CapsuleManager` : convention `build/capsule/viral/viral-deck.html`.

== Décisions

* **Un seul artefact : le deck = la porte du rendu** — le storyboard document
  reste l'entrée **humaine** (validée par le pilote) ; le deck HTML est l'entrée
  **machine** du rendu. Les deux sont écrits par `generateViralCampaign`
  (`storyboard.adoc` + `viral-deck.html`).
* **Socle FFmpeg, pas Playwright** (rappel pilote) : le deck est conçu pour la
  capture PNG→concat (`ScreenshotPlanner`), pas pour l'enregistrement temps réel
  (`ViralCaptureStrategy` force `SCREENSHOT`).
* **Tokens de marque en variables CSS** : l'identité visuelle *habille* le deck
  (CAP-CONTEXT) sans que le builder ne réinvente la charte.
* US-1b (orchestration du rendu par variante) reste à faire — le deck est
  désormais capturable.
