== Contexte

Dernier maillon du diagnostic S-145 : « 🟡 Tests rendu — aucun test
fonctionnel/BDD ne produit un MP4 ». US-1b/3 ont câblé le rendu, US-2 la durée,
mais **aucun test ne produisait un vrai fichier**. US-5 ferme ce trou : une BDD
qui produit un **vrai MP4** via le socle FFmpeg et gate sa durée.

== Livrable — feature `@viral-render` + support de rendu réel

=== `ViralRealRenderSupport` (test support)

Rejoue **exactement** les étapes du socle que `ScreenshotCaptureImpl` exécute
une fois les PNG disponibles :

* `ScreenshotPlanner.plan` → PNG/WebM par slide + concat ;
* PNG → WebM (`ffmpegPngToWebmArgs`) puis concat demuxer (`ffmpegConcatArgs`) ;
* `VideoFormatConverterImpl.convertToMp4` → MP4.

Différence : le PNG est généré **localement** (1×1 base64, ffmpeg le met à
l'échelle 1080×1920) → **pas de Chromium**, seulement `ffmpeg`/`ffprobe`
(installés dans le job `Full Tests`). Le rendu est donc **reproductible en CI**.

=== BDD

* `capsule_viral_render.feature` `@viral-render` — 2 scénarios : cible 30 s et
  cible 15 s ; les beats sont **fités** (`ViralTimeFitter.fit`) puis rendus.
* `CapsuleViralRenderSteps` — steps préfixés « real viral render » (S-088) ;
  garde `PendingException` si `ffmpeg`/`ffprobe` absents (leçon Queens S-269 : ne
  jamais échouer faute de binaire — le scénario est *pending*).
* `CapsuleViralRenderCucumberRunner` (pattern S-082) +
  `CucumberTaskSpec("cucumberTestViralRender")` **23e runner**.
* Câblé dans `full-tests.yml` (étape dédiée) ; **exclu** de l'agrégat
  `CucumberTestRunner` (qui reste pur domaine — `not @viral-render`).

== Preuves

* Le scénario produit un **vrai MP4** non vide, puis `MediaProbeUtil.probeDuration`
  vérifie sa durée contre la cible (±2 s). Scénarios *pending* hors ffmpeg.
* CI `Full Tests` (ffmpeg + ffprobe installés) exécute le scénario → preuve réelle.

== Méthode

Baby-step BDD : RED (compilation) → GREEN (compilation locale) → REFACTOR.
**Aucun test/check local** : `compileKotlin` + `compileTestKotlin` +
`compileFunctionalTestKotlin` VERTS. Preuve = CI du push (`Test` + `Full Tests`).

=== Correctif CI (premier run rouge → vert)

Le premier run `Full Tests` **timeout** (15 min) sur `cucumberTestViralRender`.
Cause racine reproduite **hors test** (diagnostic ffmpeg manuel) : un PNG **1×1**
fait **boucler** `ffmpeg -loop 1` (le démultiplexeur image ne rend jamais la
main) ; un PNG à la taille du viewport (1080×1920) rend en 3 s. **Fix** :
`ViralRealRenderSupport` génère un PNG **1080×1920** (`BufferedImage` AWT +
`ImageIO`, sans Chromium) ; les appels ffmpeg sont **bornés** (2 min par étape)
pour qu'un futur blocage échoue vite au lieu de tenir la tâche. Timeout de tâche
ramené de 15 à 5 min. Pipeline complet (PNG→WebM, concat depuis un autre CWD,
convert, probe) validé manuellement. Re-run CI : `Test` + `Full Tests` VERTS.

== Décisions

* **Socle FFmpeg sans Chromium** — `ScreenshotPlanner` + `VideoFormatConverter`
  sont le socle ; le PNG local remplace la capture Chromium (fragile en CI). Le
  rendu réel est ainsi **déterministe** et **rapide**.
* **`PendingException`** plutôt que `assumeTrue` — le runner est JUnit4/Cucumber ;
  *pending* est la voie idiomatique du skip (pas d'échec).
* **Exclusion de l'agrégat** — `CucumberTestRunner` reste pur domaine
  (`not @viral-render`), le rendu réel a son runner dédié.
