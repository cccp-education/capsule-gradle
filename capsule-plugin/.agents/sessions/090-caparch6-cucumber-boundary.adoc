== Objectif

Clôturer l'EPIC CAP-ARCH par la dernière US en attente — CAP-ARCH-6 (Cucumber
BDD boundary cross-borough E2E). L'objectif est de prouver la frontière entre la
couche LLM (CAP-ARCH-1→3 : `generateCapsuleContent`, koog pipeline, mock Ollama)
et le backend vidéo existant (CAP-29 : `generateCapsuleVideoAllLanguages`,
NoOp engines) via un scénario cucumber E2E single-language (français).

== Décisions de cadrage

. *Réduction du périmètre i18n* : le BACKLOG initial prévoyait un E2E 10 langues
  (`slider.translateDeck` → `extractSpeakerNotes` → `generateCapsuleContent` →
  `generateCapsuleVideoAllLanguages`). Décision : ne pas re-tester la chaîne
  10-langues déjà prouvée par CAP-29.5 (`multi_language_capsule.feature` S-081)
  et SLD-11 — la traduire ici serait du test redondant. Le vrai périmètre de
  CAP-ARCH-6 est la *boundary nouvelle* introduite par CAP-ARCH : la génération
  de contenu LLM câblée au backend vidéo. Le français seul prouve cette
  frontière. Single Responsibility : CAP-29.5 garde la responsabilité 10-langues.

. *Mock LLM Ollama 2 réponses alternées* : le graphe koog (`CapsulePipelineGraph`)
  issue 2 appels `/api/chat` séquentiels — `propose-context` (→ content plan
  JSON) puis `generate-speaker-notes` (→ AsciiDoc enrichi). Le mock HTTP alterne
  ses réponses via un compteur (`callCounter++ % 2`) pour servir le payload
  attendu à chaque nœud. Le content plan JSON respecte le contrat
  `ContentPlanValidator` (5 champs : deckName, languageCode, slideCount,
  speakerNotesFile, ttsScriptFile).

. *Convention de nommage boundary* : le content pipeline produit
  `<deckName>-speaker-notes.adoc` + `<deckName>-script.txt` (mono-langue source,
  sans `_lang`), tandis que le video pipeline cherche `<deckName>_<lang>-deck.html`
  + `<deckName>_<lang>-script.txt` (multi-langue traduit). Ce sont 2 conventions
  différentes — c'est exactement la boundary que CAP-ARCH-6 prouve. Le scénario
  composite pré-génère les artefacts fr (`demo_fr-deck.html` +
  `demo_fr-script.txt`) dans les dirs attendus pour le video pipeline.

. *Runner cucumber dédié* : pattern S-082 `CapsuleContextCucumberRunner` —
  `@SelectClasspathResource` + `@ConfigurationParameter(FILTER_TAGS_PROPERTY_NAME,
  "@cross-borough and not @wip and not @integration")`. Câblage
  `CucumberTaskSpec("cucumberTestArchBoundary")` dans `cucumberConventions.additionalTasks`.

. *Glue partagé `capsule.scenarios`* : le glue cucumber charge toutes les step
  classes du package, pas seulement le runner dédié. Conséquence : tous les
  steps doivent avoir des signatures uniques (bug S-088
  `DuplicateStepDefinitionException`). Steps préfixées "capsule arch boundary"
  pour éviter doublons avec `CapsuleAiSteps` (`theBuildSucceeds`,
  `theBuildOutputLogs`, `theTaskIsListedInTheOutput`).

. *Économie d'encre skip* : le scénario skip pré-génère un WebM valide de 1s
  via `ffmpeg -f lavfi -i anullsrc` (durée lisible par `ffprobe` > 0). Le
  `MINIMAL_WEBM` (header EBML seul) ne suffit pas — `ffprobe` retourne 0.0 →
  re-rendu. Le skip nécessite un WebM avec `probeDuration > 0`.
