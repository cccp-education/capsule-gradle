== Mission

Implémenter l'EPIC CAP-SPD (P0, deuxième EPIC de l'axe contexte augmenté),
5 US ~10 pts. `generateCapsuleContent` (CAP-ARCH-3) génère des speaker notes
à partir d'un deck rendu, mais le LLM ignore le "pourquoi" pédagogique
(objectifs, modalités, durée, prérequis — tous dans le SPD). En injectant le
SPD dans le contexte augmenté, le LLM ancre ses speaker notes dans les
objectifs de la session.

== Leçons

- *Audit borough privé vs public* : un borough public OSS ne doit ni
  référencer ni coupler à un borough producteur privé. Capsule valide le
  *format* SPD (`type=="SPD"`), pas le *producteur* (`source`). Le code et
  les messages publics ne nomment jamais le borough producteur.
- *N0 sealed extension locale* : quand le contrat N0 est sealed (5 variants
  `ContextChannel`), étendre le wrapper capsule-local (`CapsuleContext.
  spdSection`) plutôt que bumper le contrat N0 multi-borough.
- *Mirror pattern* : `SpdContextLoader` mirror exact `DocContextLoader`
  (object pur, pre-resolved files, `ContextChannel.Docs.truncateToTokens`)
  — cohérence domaine `capsule.context`.
- *SPD colonne vertébrale optionnelle* : sa présence enrichit le contexte,
  son absence ne bloque jamais la création de capsule vidéo (fallback
  no-op, `augmented-context.txt` sans section spd).
- *Baby-step TDD itération* : 1 test failing sur 10 (assertion incohérente
  avec le design — malformed metadata = skip metadata, adoc reste parsé).
  Correction test (pas du code) → 10/10 GREEN. Le test révèle le design, pas
  l'inverse.
- *Invariant ajusté CAP-SPD-2* : l'invariant `rendered.isBlank() ==
  channels.isEmpty()` ne tenait plus avec `spdSection` — un contexte sans
  channels mais avec SPD section a un `rendered` non-blank. Nouvel
  invariant : `rendered.isBlank() == (channels.isEmpty() && spdSection.
  isBlank())`. L'invariant suit le domaine, pas l'inverse.
- *Prompt builder référence textuelle* : le `DefaultCapsulePromptBuilder` ne
  connaît pas `SpdContext` — il lit le `augmentedContext` rendu
  (`contains("SPD Pedagogical Context")`). Découplage prompt builder /
  modèle de contexte. Le prompt est piloté par le texte rendu, pas par la
  structure objet.
