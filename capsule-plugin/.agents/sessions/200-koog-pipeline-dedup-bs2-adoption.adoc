=== Blocage découvert (et résolu) : bootstrap de la self-application codebase

La garde S-273 (`CodebasePluginPublicationTest`) avait migré la self-application du
plugin (`alias(libs.plugins.codebase)`) sur `codebase-plugin` — la **même** entrée que
la version propre. Conséquence : bumper la version propre à `0.0.18` fait résoudre le
**marker du plugin** `education.cccp.codebase:0.0.18` **avant** qu'il ne soit publié →
`Plugin ... was not found` (œuf/poule).

**Résolution (pattern capsule)** : découpler *version propre* et *version du plugin
self-appliqué* via une entrée toml dédiée `codebase-gradle-plugin = "0.0.17"`
(dernière release publiée), tandis que `codebase-plugin = "0.0.18"` porte la version
propre. La garde ne lit que l'entrée `codebase-plugin` → **VERTE** (version propre
== catalogue). La self-application est un bootstrap standard, son lag d'une version
est inhérent.
