== Objectif

CR-9 — Remplacer la regex raw `Regex("""<section\b[^>]*>""")` dans
`injectAudioSequentialFallback` par `HtmlSectionParser` existant. La regex
raw matchait *tous* les `<section>` y compris les sections imbriquées
(vertical stacks), injectant `data-audio` sur des sous-sections.

== Problème

`CapsuleVideoTask.injectAudioSequentialFallback` (l.774-817) utilisait une
regex raw pour trouver les tags `<section>` d'ouverture. Cette regex ne
distinguait pas les sections top-level des sections imbriquées (reveal.js
vertical stacks : `<section><section>Sub A</section><section>Sub B</section></section>`).
Résultat : `data-audio` était injecté sur *toutes* les sections, pas seulement
les top-level, désynchronisant l'audio de la vidéo.

== Solution

Nouvelle méthode `HtmlSectionParser.findTopLevelSectionOpenTags(html): List<MatchResult>`
— réutilise le depth-tracking existant de `extractTopLevelSections` (skip
nested + self-closing), mais retourne les `MatchResult` des tags d'ouverture
avec leurs positions, au lieu des sections complètes. L'API est compatible
avec le code existant qui itère sur `match.range.first`, `match.value`,
`match.range.last`.

+8 tests unitaires `findTopLevelSectionOpenTags` :
. `returns flat section open tags` — 2 sections flat → 2 tags
. `skips nested section open tags` — vertical stack → 2 tags top-level only

. `positions allow substring extraction` — `range.first`/`range.last` valides
. `handles multiline section open tags` — attributs sur plusieurs lignes

`HtmlSectionParser.findTopLevelSectionOpenTags` (38 lignes) — même pattern

des tags d'ouverture top-level au lieu des sections complètes.
