== Mission

Dernier candidat du backlog : **dogfooding du chemin enrichi Remotion + Manim**
(`CAP-SHORT`/`CAP-ANIM`), validé en réel. Accord pilote explicite.

== Environnement (contraintes)

* **Manim** : absent, non installable nativement (Python géré par le système,
  PEP668, pas de `pip`, pas de `sudo` pour les dev headers `pangocairo`/`cairo`).
  Résolu par un **shim Docker** : `/tmp/opencode/bin/manim` →
  `docker run --rm -v "$ROOT":"$ROOT" -w "$ROOT" manimcommunity/manim:stable manim "$@"`
  (image `manimcommunity/manim:stable` = Manim Community v0.22.0, deps natives
  fournies, zéro sudo), pointé par `-Pcapsule.manimExecutablePath`.
* **Remotion** : Node 22 présent (`nvm`). `npm install` (composition bundlée par
  le plugin) + `npx remotion render`.

binaires. Le socle FFmpeg (viral) reste, lui, validé par le dogfooding S-158.

== Constats

. ⚠️ **Nom de scène Manim sensible à la casse** : `[manim:Hello]` doit correspondre
  **exactement** au nom de classe **et** de fichier (`Hello.py`). Un mismatch
  (`[manim:hello]` alors que la classe est `Hello`) fait échouer `findRendered`
  silencieusement (le MP4 est écrit `Hello.mp4`, cherché `hello.mp4`) → le slide
  n'est **pas** animé. Visible seulement via le log « 0/N rendered ». **Candidat** :
  journaliser un warning par scène en échec (`ManimException` avalée par le
  renderer parallèle).
. ✅ Dégradations attendues : TTS `noop` → placeholder mp3 illisible par ffmpeg →
  « video remains silent » (pas un bug).
. ✅ Le chemin Remotion exige Node + `npm install` (réseau) + un Chromium headless :
  non exécutable en CI locale (comme documenté par `RemotionCaptureFunctionalTest`).
