== Décisions techniques

. **Pattern tâche composite** : `DefaultTask` vide + `dependsOn` par nom string,
   exactement comme `translateAndGenerateCapsuleVideos` (S-080). Aucune logique
   métier dans la tâche composite — le wiring se fait par dépendance Gradle.
. **Dummy deck pour `--dry-run`** : `generateCapsuleContent` résout
   `deckFile` par convention (scan `slides/misc` pour premier `.adoc`).
   En `--dry-run`, Gradle tente de résoudre les dépendances → échec si pas
   de deck. Solution : fixture `dummy.adoc` dans `slides/misc` du projet test.
. **Steps Cucumber uniques** : pour éviter `DuplicateStepDefinitionException`,
   les steps `@When`/`@Then` sont préfixés ("distrib", "content and videos")
   au lieu de réutiliser les patterns génériques de `CapsuleStepDefinitions`.
. **Runners dédiés** (bug S-082) : chaque feature cucumber a son runner
   `@SelectClasspathResource("features/<file>.feature")` + `@ConfigurationParameter(FILTER_TAGS_PROPERTY_NAME)`
   pour contourner le bug où `FEATURES_PROPERTY_NAME` du `CucumberTestRunner`
   global écrase la system property.
