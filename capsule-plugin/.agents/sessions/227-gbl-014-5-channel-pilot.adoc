== Contexte

US-5 (GBL-014) doit aligner les 20 dépôts publics sur le canal dual :
`ci/run.sh` passe `-Pchannel`, shims `conventions 0.0.18`, settings
conditionnels. Cette session livre un **pilote** sur `capsule-gradle` (dépôt
public, CI migrée GBL-013) avant généralisation.

== Changements

|===
| Fichier | Contenu

| `settings.gradle.kts` (racine)

  ; le dépôt JitPack et le shim `useModule(conventions 0.0.18)` sont déclarés
  **seulement** si `channel=jitpack`.

| `capsule-plugin/settings.gradle.kts`

== Limites du pilote

* `CHANNEL=central` n'est pas encore exécutable : les markers
  `education.cccp.build.*` **0.0.18** ne sont pas publiés sur Central/Portal
  (JitPack seulement) ; le mode central sera utilisable après US-7
  (reset 2026-12-01).
* Le mélange `bakery` (`platform("education.cccp:workspace-bom:…")` dans un
  build JitPack) n'est **pas** traité ici.
* Les 19 autres dépôts gardent le shim `0.0.17` et un `ci/run.sh` sans
  `-Pchannel`.

== Modèle de rollout (reste US-5)

. Pour chaque dépôt : envelopper le dépôt JitPack + le shim dans
   `if (publicationChannel == "jitpack")`, bumper le shim à `0.0.18`.
. `ci/run.sh` : `channel="${CHANNEL:-jitpack}"` + `-Pchannel="$channel"` sur
   chaque invocation Gradle ; ajouter `verifyChannel` au job qui n'exécute pas
   `check`.
. Cas `bakery` : retirer la plateforme Central du build JitPack (alignement par
   le catalogue JitPack), ou basculer le dépôt en `channel=central`.
. Preuve par dépôt : CI du commit + `verifyChannel` vert.

Rapport global : `workspace-bom` S-359 (BOM) + conventions S-050 (US-1/2).
