= Session 091 — CAP-CR3-2 Mode strict anti-NoOp (EPIC CAP-CR3-2 US-1→4)

_Date_ : 2026-08-10
_Type_ : feat+ddd+tdd+bdd
_Score_ : 9/10

== Objectif

Livrer l'EPIC CAP-CR3-2 (Mode strict anti-NoOp) — le P0 de l'EPIC CAP-CR3
(revue CR-GLOBALE-003 solidité vidéo). L'objectif est d'empêcher le « faux
positif » : `check` vert + livrable illisible quand un engine (Piper, espeak,
Playwright, ffmpeg, manim) est absent et silently remplacé par un NoOp
placeholder. En strict mode, le build doit FAIL avec un message actionable.

== Cadrage (US-0 implicite)

*Audit code* : 6 fonctions `resolve*` retournent silencieusement un engine
NoOp quand l'outil réel est absent. Le pattern est partout le même :
`if (engine.isAvailable()) engine else NoOpXxxEngine()`.

*Inventaire des 6 fallbacks silencieux* :
. `CapsuleBuildTask.resolveTtsEngine` (piper absent, espeak absent, unknown)
. `CapsuleVideoTask.resolveTtsEngine` (piper absent, espeak absent, else)
. `CapsuleVideoTask.resolvePlaywrightCapture` (Playwright absent)
. `CapsuleManager.resolveManimEngine` (manim absent)
. `CapsuleManager.resolveManimVideoMixer` (ffmpeg absent)
. `CapsuleManager.resolveSubtitleBurnInService` (ffmpeg absent)

*Note* : `resolveManimParallelRenderer` n'est pas un fallback d'indisponibilité
— `NoOpManimParallelRenderer` est un mode séquentiel légitime (parallelism ≤ 1).
Hors périmètre.

== Décisions de cadrage

. *DSL* : `capsule.strictMode` (Boolean, défaut `false`) — rétrocompatible.
. *4 sources* : ENV `CAPSULE_STRICT_MODE_ENABLED` < props
  `capsule.strictMode.enabled` < YAML `strictMode.enabled` < CLI
  `-Pcapsule.strictMode.enabled`.
. *Portée* : 6 fallbacks deviennent erreurs quand `strictMode = true`. Le
  `noop` explicite (`ttsEngine = "noop"`, `ffmpegPath = "noop"`) reste
  légitime pour tests → non concerné.
. *Exception* : `IllegalStateException` avec message exploitable nommant
  l'engine, le path, et suggérant `strictMode=false` ou `install <tool>`.
. *Domaine* : `capsule.config` déjà existant (`CapsuleConfig`,
  `CapsuleConfigMerger`, `CapsuleConfigLogger`) → étend `CapsuleConfig` avec
  `StrictModeConfig` (1 champ `enabled: Boolean`). Pas de nouveau domaine.
. *Helper* : `StrictModeGuard` (object pur, domaine `capsule.config`) —
  `requireAvailable(strict, engineName, isAvailable, path)` lève si
  `strict && !isAvailable`. Testable unit pur.

== US-1 — StrictModeConfig + StrictModeGuard (domaine pur)

*Niveau* : unit tests.

*RED* : 10 tests écrits (7 `StrictModeGuardTest` + 3 `StrictModeConfigTest`)
avant le code de production. Compilation échoue (`Unresolved reference
StrictModeGuard`).

*GREEN* : 2 fichiers prod créés :
. `StrictModeConfig.kt` — data class 1 champ `enabled: Boolean = false`.
. `StrictModeGuard.kt` — object pur, `requireAvailable(strict, engineName,
  isAvailable, path)` : no-op si `!strict || isAvailable`, sinon
  `IllegalStateException` avec message :
  `"strictMode is enabled: <engine> not available at '<path>'.
  Disable strictMode (capsule.strictMode=false) or install <engine>."`.
  Path segment omis si blank (pas de dangling ` at ''`).

*Résultat* : 10 tests unit VERT (+10).

== US-3 — Wiring 6 resolve* + functional tests

*Niveau* : functional tests.

*RED* : 4 tests `StrictModeFunctionalTest` écrits (default NoOp préserveré,
strict + piper absent → FAIL, strict + noop explicite → OK, CLI flag strict
→ FAIL). 2 tests échouent (strict DSL + strict CLI : le build ne fail pas
avec le bon message — `ttsFallbackEnabled = false` court-circuitait avant
le guard avec une `TtsException` générique).

*GREEN* : 6 `resolve*` branchés avec `StrictModeGuard.requireAvailable` :
. `CapsuleBuildTask.resolveTtsEngine` — piper absent + fallback enabled →
  guard avant NoOp (espeak absent idem). `noop` explicite skip guard.
. `CapsuleVideoTask.resolveTtsEngine` — piper/espeak absent → guard.
. `CapsuleVideoTask.resolvePlaywrightCapture` — Playwright absent → guard
  (path = `chromiumExecutablePath`).
. `CapsuleManager.resolveManimEngine(config, strict)` — param `strict`
  ajouté (défaut `false` pour rétrocompatibilité).
. `CapsuleManager.resolveManimVideoMixer(ffmpegPath, strict)` — idem.
. `CapsuleManager.resolveSubtitleBurnInService(ffmpegPath, style, strict)` —
  idem. 3 appelants dans `CapsuleVideoTask` passent
  `strict = capsuleExtension.strictMode.get()`.

*Correction test* : `ttsFallbackEnabled` mis à `true` dans les tests strict
pour que le chemin passe par le guard (fallback enabled → warn → guard →
NoOp), pas par l'exception `TtsException` (fallback disabled).

*Résultat* : 4/4 functional VERT. 44 functional total (+4). Zéro régression.
