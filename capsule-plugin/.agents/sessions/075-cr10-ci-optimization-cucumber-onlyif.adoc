== Objectif

Le skipper sauf demande explicite (`-PrunCucumber` ou `CI=true`) pour
garder `./gradlew check` rapide en local.

== Méthode

Baby-step DDD/TDD/BDD, 3 niveaux de tests :
1. **Unit** (pur) — `CucumberTestGuardTest` (domaine `capsule.ci`)
2. **Functional** — supprimé (scope mismatch — `cucumberTest` est câblé dans le
   build script du plugin, pas exposé aux projets consommateurs)
3. **BDD Cucumber** — `cucumber_skip.feature` (4 scénarios `@ci`)

== Livrables

=== Domaine `capsule.ci` (nouveau)

`src/main/kotlin/capsule/ci/CucumberTestGuard.kt` — data class pure (4 méthodes) :
- `shouldRun(): Boolean` — `hasRunCucumberProperty || isCi`
- `shouldSkip(): Boolean` — négation
- `skipReason(): String` — message explicatif si skip, blank si run

=== Câblage build.gradle.kts

`afterEvaluate` block (lignes 20-35) :
- `val hasRunCucumber = project.hasProperty("runCucumber")`
- `val isCi = System.getenv("CI") == "true"`
- `tasks.named("cucumberTest").configure { onlyIf { shouldRun } }`
- `doFirst { if (!shouldRun) logger.lifecycle(...) }`

Note : logique inlinée dans le build script car le script ne peut pas importer
le classpath `main` du projet lui-même (contrainte precompiled script plugins).
La classe `CucumberTestGuard` documente et teste le contrat (pur domain).

=== Tests unitaires

`src/test/kotlin/capsule/CucumberTestGuardTest.kt` — 7 tests :
- `shouldRun returns true when runCucumber property is present`
- `shouldRun returns true when CI env var is true`
- `shouldRun returns true when both runCucumber and CI are active`
- `shouldRun returns false when neither runCucumber nor CI is active`
- `shouldSkip is the negation of shouldRun`
- `skipReason explains cucumber task is skipped when neither flag is active`
- `skipReason is blank when guard should run`

=== BDD Cucumber

`src/test/features/cucumber_skip.feature` — 4 scénarios `@ci` :
- `cucumberTest is skipped when no flag is active`

- `cucumberTest runs when both runCucumber and CI are active`

`src/test/kotlin/capsule/scenarios/CucumberSkipSteps.kt` — 5 step defs :

- `Then the guard should skip the cucumber test`

- `And the skip reason should mention {string}`
- `And the skip reason should be blank`

== Bug préexistant découvert

`CucumberTestRunner` (filtre `not @wip and not @integration`) ne lance que
`capsule.feature`. Les autres features (`capsule_speaker_notes`,
`consolidated_capsule_model`, `parallel_capture_timeout`,
`translate_and_extract_speaker_notes`, `cucumber_skip`) ne sont pas lancées
par ce runner. Seul `CucumberIntegrationTestRunner` (filtre
`@integration or @manim`) tourne et skippe les scénarios non-`@integration`.

Ce bug de découverte JUnit Platform préexiste à cette session (depuis au moins
S-071 qui mentionne "64 cucumber tests" — ce chiffre correspond aux scénarios
`@integration`/`@manim` uniquement). À investiguer en session future : les
features non-`capsule.feature` sont peut-être filtrées par un mécanisme
non documenté dans le `CucumberConventionsPlugin` ou la config JUnit Platform.
