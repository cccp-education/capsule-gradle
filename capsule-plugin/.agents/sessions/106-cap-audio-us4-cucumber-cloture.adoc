    wiring + economy-of-ink guard + factory dispatch, pas le rendu audio
    (couvert par US-2 unit tests `AudioPostProcessorTest` 17 unit).

. **RED — Feature `capsule_audio_post.feature`** — 4 scénarios `@audio @post` :
  - Default audio post config is a no-op skip (economy of ink) — default
    `bgmEnabled=false` + `duckingEnabled=false` → `applyAudioPostIfEnabled`
    returns early (no "Audio post:" log), WebM produced.
  - BGM enabled with NoOp processor degrades and keeps original WebM —
    `bgmEnabled=true` + `ffmpegPath="noop"` → `resolveAudioPostProcessor`
    routes to `NoOpAudioPostProcessor` → `process()` returns `false` →
    "Audio post:" log (degraded warn), WebM produced (original kept).
  - Ducking enabled without BGM triggers loudness-only fallback with NoOp
    degraded — `duckingEnabled=true` + `bgmEnabled=false` → passes the
    economy-of-ink guard (either flag triggers), `AudioPostCommand.
    buildFilterGraph` falls back to loudness-only (ducking without BGM
    is meaningless), NoOp → "Audio post:" log, WebM produced.
  - Ducking and BGM enabled with NoOp processor degrades and keeps original
    WebM — `bgmEnabled=true` + `duckingEnabled=true` + `ffmpegPath="noop"`
    → both flags trigger, NoOp → "Audio post:" log, WebM produced.
