== Contexte

Demande pilote : évaluer si `capsule-gradle` peut devenir le **moteur des
campagnes de viralité** YouTube/TikTok des produits de talaria et de la
technologie cccp.education. Ce document est le **cadrage** de l'EPIC qui
réoriente le borough (DORMANT depuis S-137, 30 EPICs terminés).

Le borough a été conçu comme générateur de **capsules pédagogiques longues**
(deck → vidéo narrée multi-langue). Le viral court-forme est un **usage
nouveau** : format vertical, durée 15-60 s, hook 3 s, batch multi-plateforme,
métadonnées et publication. Cet EPIC réutilise massivement l'existant.

=== Constat structurel du crop

`deployCapsule` recadre 16:9 → 9:16 par `scale=...:force_original_aspect_ratio=increase,
crop=1080:1920` (`CapsuleDistribTask.kt:92`). Un slide pédagogique 16:9 recadré
en portrait **ampute le contenu latéral**. Le levier correct est le **rendu
vertical natif**, pas le recadrage. Le recadrage peut rester une stratégie de
secours (deck 16:9 existant), mais pas le chemin nominal d'une campagne.

=== Décision structurante — méthode FFmpeg, PAS Playwright temps réel

*Direction pilote (2026-10-09)* : les campagnes virales s'appuient sur la
**méthode FFmpeg** (assemblage déterministe), **pas** sur l'enregistrement vidéo
temps réel Playwright. **Remotion et Manim sont renforcés** comme couches
d'**enrichissement du contenu** — ce n'est pas un choix antagoniste, c'est une
chaîne à deux étages.

Les 3 stratégies existantes (`CaptureStrategy`, `CapsuleConfig.kt:93-96`) :

[cols="1,3,2", options="header"]
|===
| Stratégie | Principe | Rôle CAP-VIRAL

| `PLAYWRIGHT`
| Enregistrement vidéo du navigateur en temps réel (`.recordVideo`)
| ❌ **exclu** — timing non déterministe, fragilité, navigateur headless lourd
| `SCREENSHOT`
| PNG par slide → **encode FFmpeg durée exacte** → **concat demuxer** (`ScreenshotPlanner.kt`, `ScreenshotCaptureImpl`)
| ✅ **socle** — assemblage déterministe, reproductible, cadence exacte ; base du format court
| `REMOTION`
| Rendu frame-par-frame animé (React) — **composeur enrichi** qui embarque les animations Manim par slide
| ✅ **enrichissement** — mouvement, transitions, fond animé, intégration Manim
|===

*La chaîne à deux étages (pas un choix, une complémentarité)* :

```
contenu enrichi        Remotion (React)  ── embarque ──▶  animations Manim (schémas animés)
   │                                                       (data-manim → stageManimAssets)
   ▼
assemblage                PNG/frames → FFmpeg durée exacte → concat demuxer (-c copy)
   │
   ▼
livrable viral        MP4/H.264 1080×1920 + TTS + sous-titres burn-in + loudnorm
```

.Le socle FFmpeg (déterminisme)
* La cadence est **exacte par slide** (`-t <durée>`), le montage est un **concat
  demuxer** (`-c copy`), donc **sans ré-encodage** — c'est ce qui rend le format
  court viral fiable et reproductible au frame près.
* `PLAYWRIGHT` (enregistrement temps réel) est **écarté** : timing non
  déterministe, incompatible avec une campagne batch.

.L'enrichissement Remotion + Manim (déjà intégré)
* **Remotion** (`RemotionCapture`, CAP-ANIM) est le **composeur frame-par-frame**
  qui produit le mouvement : transitions d'entrée, dérive lente, cross-fades —
  là où `SCREENSHOT` ne tient qu'une image figée par slide. Sortie MP4/H.264
  (`outputExtension() == "mp4"`, mesuré 13.1 fps H.264 vs 9.1 VP8).
* **Manim** (`ManimEngine`, `ManimParallelRenderer`, `ManimVideoMixer`) produit
  des **schémas animés** (courbes, formules, transformations) attachés à une
  slide via l'attribut `data-manim` ; Remotion les charge (staging `public/`),
  mesure la durée du clip et accorde l'animation à la voix
  (`RemotionCapture.stageManimAssets`, `RemotionCapture.kt:128-170`). C'est le
  différenciateur visuel d'une vidéo pédagogique virale.
* Les deux sont **déjà câblés** (Manim → Remotion → pipeline) : CAP-VIRAL les
  **renforce**, ne les réintroduit pas.

*Contrainte à lever* : la méthode `SCREENSHOT` rasterise aujourd'hui ses PNG
**via Playwright** (`ScreenshotCaptureImpl.shootSlides`,
`PlaywrightManager.kt:249-280`). Le cadrage retient la **chaîne d'assemblage
FFmpeg** (PNG → durée exacte → concat) ; le rasteriseur PNG est un point
d'extension à rendre découplable (pipeline image-native, sans enregistrement
vidéo temps réel). Le socle FFmpeg reste le chemin par défaut ; **Remotion est
le chemin enrichi** quand la campagne exige du mouvement.

*Conséquence sur CAP-VIRAL* :
- Le batch multi-plateforme (US-6) et le format court (US-3) reposent sur la
  cadence exacte FFmpeg (durée cible 15-60 s maîtrisée au frame près).
- Le rendu vertical natif (US-2) = cadrage 1080×1920 **portrait** ; le socle
  FFmpeg assemble, **Remotion enrichit** (mouvement + Manim) sans rejouer le
  montage.
- `PLAYWRIGHT` reste disponible pour les capsules pédagogiques legacy
  (backward compat), mais **interdit** comme chemin CAP-VIRAL.

== Décisions architecturales

. [x] **EPIC `CAP-VIRAL`** — nouveau domaine `capsule.viral`, ne modifie pas
   les domaines pédagogiques existants (additif, backward compat).
. [x] **Méthode FFmpeg, pas Playwright temps réel** : le chemin nominal viral est
   PNG → encode FFmpeg (durée exacte par slide) → concat demuxer (`-c copy`).
   `PLAYWRIGHT` (enregistrement vidéo temps réel) = **exclu du viral**.
. [x] **Remotion + Manim renforcés (enrichissement)** : Remotion est le
   **composeur frame-par-frame** (mouvement, transitions) qui **embarque les
   animations Manim** par slide (`data-manim`). Deux étages complémentaires au
   socle FFmpeg, **pas** un choix antagoniste. Déjà câblés (CAP-ANIM,
   `RemotionCapture`/`ManimEngine`) — CAP-VIRAL les intensifie pour le viral.
. [x] **Rendu vertical natif prioritaire** : cadrage 1080×1920 **portrait** ;
   socle FFmpeg assemble, Remotion enrichit (mouvement + Manim) ; le crop
   `deployCapsule` devient opt-in/fallback (deck 16:9 legacy).
. [x] **Format court** : `ViralConfig` — durée cible, preset plateforme
   (YOUTUBE_SHORT / TIKTOK / REELS), hook, CTA. Section `viral` de `CapsuleConfig`
   (defaults backward compat).
. [x] **Hooks/CTA générés par LLM** via `pipeline/CapsuleLlmService` (codebase
   N1 déjà branché) — pas de nouveau socle LLM.
. [x] **Métadonnées campagne** : `CampaignMetadata` (titre, description,
   hashtags, caption) par plateforme, généré par LLM.
. [x] **Batch multi-plateforme** : matrice (langue × plateforme × durée) →
   N variantes en une commande, Économie d'Encre (skip si artefact valide).
. [x] **Publication API** : hors scope CAP-VIRAL (EPIC aval N4, cf. GBL-002) —
   CAP-VIRAL produit les artefacts + métadonnées, pas l'upload.
. [x] **CI d'abord** (US-1) : corriger le fallback creds avant toute feature,
   sinon pas de preuve.
. [x] **Baby-step DDD/TDD/BDD strict** + runner Cucumber dédié (pattern S-082)
   + steps préfixés (pattern S-088).
