== Livrable — PRT-07 timeline déterministe (US-1, pur)

Porté de `prepa_electricite_complet/montage_audio.py` : « chaque scène dure un nombre
ENTIER d'images […] le son et l'image ne peuvent donc pas dériver, même sur une heure ».

* **Domaine pur** `capsule.timeline` :
  - `TimelineConfig(fps=30, leadSeconds=0.0, tailSeconds=0.0, avanceSeconds=0.0)` —
    invariants (fps > 0, durées >= 0) ;
  - `TimelineEntry(slideIndex, startFrame, frameCount>=1, voiceStartFrame>=startFrame)` ;
  - `Timeline(fps, entries)` avec `totalFrames`/`totalSeconds` ;
  - `TimelineBuilder.framesFor/secondsFor` + `build(durations, config)`.
* **Modèle** : ancré sur la voix, contigu — chaque slide occupe les images de son audio
  (min 1), le premier après le `lead`, le dernier porte aussi le `tail`, et la voix d'une
  slide (hormis la première) démarre `avance` images après son visuel (le visuel précède
  la voix — `AVANCE` de prepa). Défauts 0 → durée = `round(duree × fps)` par slide, total =
  Σ (comportement neutre).
* **Câblage observable (sans changer le comportement)** : `CapsuleVideoTask.execute`
  construit la timeline à partir des `slideDurations` et journalise
  `Timeline: N frames at F fps (Xs)`. Le câblage capture/sous-titres/économie d'encre est
  l'**US-2** de l'EPIC timeline.
* **Tests** : `TimelineBuilderTest` (8 unit : contiguïté, arrondi, lead/tail, avance,
  durée nulle = 1 image, inverse `framesFor`/`secondsFor`, fps invalide) +
  `capsule_timeline.feature` (3 scénarios `@timeline`, runner dédié 33e
  `cucumberTestTimeline`) + `TimelineFunctionalTest` (le log `Timeline:` apparaît).
