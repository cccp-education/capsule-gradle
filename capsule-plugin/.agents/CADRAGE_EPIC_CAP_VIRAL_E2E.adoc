== Objectif

Clore les **3 dettes e2e** restantes du moteur viral (diagnostic S-145,
`BACKLOG.adoc` § CAP-SHORT) : le domaine viral existe (CAP-VIRAL 14/14,
CAP-SHORT 5/6) mais trois briques sont **sans usage en production**.

L'EPIC ne modifie pas le domaine CAP-VIRAL : il **branche** la production là où
le domaine est déjà complet, pour que le livrable (`CampaignBundle` + MP4
verticaux + assets) soit **cohérent avec lui-même**.

== Décisions

. **Domaine pur d'abord** : chaque US livre un objet pur testable (unit) avant
  tout câblage Gradle ; le câblage est un **adaptateur mince** (pattern maison).
. **C1 — gate manifeste ↔ fichiers** (US-1) : nouvel objet pur
  `ViralCampaignGate` + parseur `CampaignBundleSerializer.parseManifest` (round-trip)
  + tâche `validateViralCampaign` (groupe `verification`, `dependsOn
  renderViralVariants`). Vérifie que chaque `videoFile` (et `thumbnailFile`
  non-blanc) existe et est non vide ; échec en mode strict, avertissement sinon
  (dégradé — cohérent avec `RenderViralVariantsTask`).
. **C2 — thumbnail prod** (US-2) : `RenderViralVariantsTask` produit
  `<variant.id>-thumb.png` (via `ViralThumbnailPlanner` + rendu carte) et
  `GenerateViralCampaignTask` alimente `thumbnailFor` pour que le bundle pointe
  l'asset réel. `capsule.chapters.CardRenderer` fournit le HTML ; la capture PNG
  réutilise le socle existant.
. **C3 — karaoké prod** (US-3) : le pipeline sous-titres viral produit un `.ass`
  karaoké par variante via `KaraokeSubtitleBuilder` + `formatAssTimestamp`,
  câblé dans le chemin de rendu.
. **Économie d'Encre** : aucun re-rendu d'un asset valide ; la gate est
  cheap (existence + taille).
. **English only** : code, Gherkin, commentaires.
. **Publication** : aucune dans cet EPIC sans accord pilote (Règle 2). Le bump
  `0.0.3` est un candidat distinct (description POM neutralisée S-153).
