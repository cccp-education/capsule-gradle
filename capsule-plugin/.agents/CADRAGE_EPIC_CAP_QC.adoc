== 1. Objet et origine

La revue de code de `prepa_electricite_complet` (`code_review.adoc`) a identifié des
**techniques** — jamais du code, jamais du contenu — qui manquent à `capsule` et qui
relèvent du **contrôle qualité et de l'intégrité** de la fabrication vidéo. Le dépôt source
est une usine Python de cours vidéo (18 chapitres) : synthèse vocale, QC de voix par
reconnaissance de la parole, sous-titres, tableau noir LaTeX, timeline, contrôle qualité
visuel, publication. Le portage retient l'**utilitaire** et laisse le **contenu**.

== 2. Frontière — ce qu'on porte, ce qu'on ne porte pas

* *On porte* : les **techniques** de fabrication/contrôle vidéo, en **réécriture Kotlin**
  (objets purs + ports/adapters).
* *On ne porte pas* : le **contenu** du cours (œuvre dérivée d'un manuel) ; le **moteur de
  rendu maison** (Java2D / LaTeX serveur — PRT-11 **CADUQUE**, cf. § 4 et `code_review.adoc`) ;
  un contrat N0 MEMPHIS (le portage est **capsule-scoped**, comme la résilience LLM S-162).
* *Licence* : `prepa` n'a pas de LICENSE → **idées/patrons seulement**, jamais de code
  recopié ; `OssVocabularyGuardTest` verrouille la généricité (aucun `formation`/`FPA`).

== 4. Décision fondatrice — pas de quatrième voie de rendu

Les trois voies de capture (`PLAYWRIGHT`, `SCREENSHOT`, `REMOTION`) dépendent **toutes** de
Chromium (`REMOTION` via `@remotion/renderer`). Un moteur Java2D + JLatexMath serait un
**navigateur en moins bien** ; les bénéfices prêtés sont déjà couverts. Décision : porter
l'utilitaire **hors rendu** ; si un serveur sans navigateur est requis, **pré-rasteriser en
CI** (Chromium au build, FFmpeg au runtime). Détail : `code_review.adoc` § 8.

== 6. Décisions transverses (invariants de tous les portages)

. **Opt-in** : toute option nouvelle est un `Property` **défaut false** → backward compat,
   zéro régression.
. **4 sources de config** : DSL `capsule {}` > CLI `-Pcapsule.*` > `gradle.properties` > ENV
   (`CapsuleConfig` + extension + `CapsuleConventions` + `CapsuleConfigMerger` + `pushConfigIntoExtension`).
. **Objet pur d'abord** : la décision est un objet **sans I/O** (testable sans outil externe) ;
   l'I/O vit dans un port/adapter (`TtsEngine`, `ManimEngine`, `SpeechRecognizer`…).
. **Économie d'encre** : ne pas refaire ce qui a déjà produit un artefact valide (PRT-06
   signature + PRT-04 décodage).
. **Dégradation** : un outil absent dégrade (warning), `strictMode` → échec ; un outil
   externe (ASR) n'est **jamais** un prérequis de `check` (`assumeTrue` en CI).
. **Méthode** : baby-step **DDD/TDD/BDD** (unit → fonctionnel → cucumber) ; runner Cucumber
   dédié par feature (S-082), steps préfixés (S-088). **Local = Build, Tests = CI**.
