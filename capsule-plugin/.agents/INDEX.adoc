== EPIC CAP-MODEL — Unification modèle capsule.feed ↔ capsule.CapsuleScript (Session 069 — Cadrage)

_Vision_ : L'EPIC SLD-11 (S-058) a expulsé `slider.capsule` côté capsule en créant le
domaine `capsule.feed` (`AsciidocSpeakerNoteParser`, `CapsuleFeedModels`, `CapsuleScriptWriter`,
`CapsuleFeedTaskDomain`, `CapsuleFeedTaskRegistrar`). Mais l'ancien modèle
`capsule.CapsuleModels` (`SlideType` enum, `SlideSegment` 5 champs avec `type`+`manimScene`,
`CapsuleScript` avec field `slides`) reste vivant côté consommateurs vidéo
(`CapsuleVideoTask`, `ManimParallelRenderer`, `SubtitleTimingCalculator`, `CapsuleBuildTask`,
`CapsuleScriptTask`, `CapsuleCompositeContextTask`).

_Doublon divergent_ :
* `capsule.feed.SlideSegment` : 3 champs (index, title, speakerNote), invariants stricts, pas de `type`.
* `capsule.SlideSegment` : 5 champs (+ `type: SlideType`, `manimScene: String?`), pas d'invariants.
* `capsule.feed.CapsuleScript` : field `segments`, invariant `deckName` non-blank, `isEmpty`.
* `capsule.CapsuleScript` : field `slides`, pas d'invariant.

_Round-trip lossy_ : `extractSpeakerNotes` produit un `.txt` via `CapsuleScriptWriter`
(format `=== CAPSULE SCRIPT ===` / `--- SLIDE n : title ---`), puis `CapsuleManager.parseScript`
(64 lignes) reparse ce même `.txt` pour reconstruire un `capsule.CapsuleScript` riche
(extrayant `[manim:SceneName]` et `[html]` du titre). Le write→parse est une perte :
le modèle source `capsule.feed.CapsuleScript` connaît déjà les titres propres, mais
le writer les sérialise avec marqueurs puis le parser les re-extrait.

_Boundary cible_ :
- UN seul modèle : `capsule.feed.SlideSegment` (étendu avec `type` + `manimScene`) +
  `capsule.feed.CapsuleScript` (renommé field `segments` → gardé, invariant `isEmpty`).
- `SlideType` enum migre vers `capsule.feed`.
- `CapsuleScriptWriter` préserve le format `.txt` (rétrocompatibilité contrat slider-side
  + tests Cucumber existants), mais sérialise `type`/`manimScene` via marqueurs
  `[manim:SceneName]` / `[html]` déjà utilisés.
- Nouveau `CapsuleScriptReader` (object pur, `capsule.feed`) remplace `CapsuleManager.parseScript`
  — parse `.txt` → `capsule.feed.CapsuleScript`. Round-trip write→read idempotent.
- `CapsuleManager.parseScript` supprimé (dead code après migration consommateurs).
- `capsule.CapsuleModels.kt` supprimé (`SlideSegment`, `CapsuleScript`, `SlideType` retirés).
- `CapsuleExtension`/`CapsuleConventions` restent dans `capsule` (pas du modèle métier).

_Consommateurs à migrer_ (5 fichiers prod) :
. `CapsuleVideoTask.kt` — 12 références `CapsuleScript`/`SlideSegment`/`SlideType`
. `ManimParallelRenderer.kt` — 3 signatures `List<SlideSegment>`
. `SubtitleTimingCalculator.kt` — 1 signature `List<SlideSegment>`
. `CapsuleBuildTask.kt` — 1 appel `parseScript`
. `CapsuleScriptTask.kt` — 1 appel `parseScript`
. `CapsuleCompositeContextTask.kt` — 1 appel `parseScript`
