== Session 138 — CAP-VIRAL US-0 : cadrage moteur de viralité ✅

Cadrage (gouvernance pure, zéro code) de la réorientation de `capsule-gradle`
vers les **campagnes de viralité YouTube/TikTok** des produits talaria + cccp.education.

=== Constat

Audit au code réel :

* **Moteur de capsules pédagogiques : 4,5/5** (30 EPICs, ~1166 unit / 75 functional
  / 21 cucumber dédiés, publié Central 0.0.1, TTS 22 langues, sous-titres,
  loudnorm, 3 stratégies de capture).
* **Moteur viral : 2/5** — gap bloquant : vertical 9:16 = **crop destructif**
  (`CapsuleDistribTask.kt:92`), pas de format court 15-60 s, pas de hooks 3 s,
  pas de batch multi-plateforme, CI **rouge** (`ossrhUsername not found`,
  `settings.gradle.kts:30-31`).

=== Décision structurante — chaîne à deux étages

* **Socle FFmpeg** (déterministe) : PNG par slide → `-t <durée>` (cadence exacte)
  → concat demuxer `-c copy` (sans ré-encodage). **Playwright temps réel écarté**
  du viral (`CaptureStrategy.PLAYWRIGHT` = legacy pédagogique).
* **Enrichissement Remotion + Manim** (déjà câblés CAP-ANIM) : Remotion =
  composeur frame-par-frame (mouvement, transitions) qui embarque les animations
  Manim par slide (`data-manim` → `RemotionCapture.stageManimAssets`,
  `RemotionCapture.kt:128-170`, accord clip/voix). Renforcés pour le viral.
